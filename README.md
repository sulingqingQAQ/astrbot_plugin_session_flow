## 能看到什么

- **会话页**：会话卡片（回合数/报错/token/最近一句）→ 回合列表 → 单轮详情
  （用户原话 / 思考 / 工具调用+参数 / 工具结果 / 回复 / 报错 / 注入块 / system prompt 全文）。
  回合列表按页翻（见下面“分页与搜本对话”），新的在上；运行中的会话 3 秒刷一次标记；暗色跟系统。
- **检索页**：`tool:名`、`err:`/`err:文字`、`user:文字`、`umo:片段`、自由词
  （3 字及以上走全文索引，否则按包含匹配，多个条件取交集；展示的命中优先挑真含检索词的事件）。
  命中按运行时间从新到旧整体排序，凑够条数就停（不读完所有命中运行的事件）。
- **旧档页**：从 AstrBot 旧档（conversations / provider_stats /
  platform_message_history）一次性导入历史回合，时间优先用 checkpoint，
  其次 provider_stats，都没有才估算；已导入过的对话按 updated_at 跳过。
- **管理页**：库状态、**谁在往上下文里塞东西**（按插件统计注入量）、**导出时屏蔽哪些内容**（规则编辑）、运行诊断、按保留天数清理（删除按钮要点两次确认，4 秒内有效）。
- **顶部横幅**（v0.1.8）：只在真出问题时才亮（见下面“顶部横幅”）。
- **system prompt 对比上一轮**（v0.1.9）：单轮详情右上角有一个小块，写这一轮的完整 system prompt 比上一轮改了几处、是谁改的；点「看改了哪里」把改动处在完整提示词里画红框（见下面“system prompt 对比上一轮”）。

## 分页与搜本对话（v0.1.4 起）

会话详情里的回合列表：

- **分页条**：每页 20 / 50 / 100 条（选了记在这台浏览器里，下次沿用）、上一页 / 下一页、
  “第 N / M 页 · 共 X 轮”，页码框可以直接改数字回车跳页（超出范围收到最后一页）。
  新的在上，第 1 页是最新。你停在第 3 页时又来了新回合，每页的内容会错位一两条，翻一下就对了。
- **列表自己滚**：回合卡片放在固定高度的框里，框里有粗一点的圆角灰色滚动条；
  搜索框、分页条留在框外面，翻页时不用先滚到页底。点左边的会话后，右边卡片会自动滚到视野上部。
- **搜本对话**（标题右边）：只搜当前这个会话（会话 ID 精确匹配，不会串进“前面一样、后面多几位”的别的会话）。
  - 直接打字是自由词；也认 `tool:骰子`、`err:`、`err:文字`、`user:文字`，多个条件取交集。
    3 个字及以上走全文索引，1～2 个字按包含匹配。
  - 左边的下拉选内容类型：提问 / 回复 / 思考 / 工具 / 注入 / 报错。只在这一类内容里搜；
    只选类型、不写词，就列出含这一类内容的回合（比如“报错”= 出过错的回合）。
  - 回车或点“搜索”执行；结果直接替换下面的回合列表，同样分页：卡片上多出最多 3 条命中片段
    （按内容种类配色，检索词高亮）。点卡片进详情，词在正文里高亮，含词的长文本自动展开，并滚到第一处命中。
  - 点输入框里的 ×、按 Esc、或把下拉选回“全部内容”，回到不搜索的列表，停在进入搜索前的那一页。
  - 不搜完整 system prompt（它单独存、每轮几乎一样，搜出来全是重复）。

## 注入怎么认（v0.1.2 起）

“注入”= 别的插件在这一轮请求里往模型塞的额外内容。三个来源都会单独列成「注入」事件，并标来源：

- **用户消息里多出来的文本块**（`extra_user_content_parts`，如 `<system_reminder>`、记忆插件的块）；
- **系统提示词里被追加 / 前置 / 改写的部分**：在最高优先级的 `on_llm_request` 钩子里先存一份原文，
  最低优先级钩子里再和最终发给模型的对比，多出来的部分按 `<标签>…</标签>` 拆开，标签名当注入名，
  没标签的叫“系统提示词追加 / 前置 / 改写”；
- **提问被别的插件加了前缀 / 后缀**（如 `[群聊·小明] `），叫“提问前置 / 追加”。

限制：只有「比你的插件优先级低」的改动看得到——要是某个插件用比 999999 更高的优先级抢在我前面改，
那部分会被当成原文。被换掉的原文（“改写”）只留前 2000 字。

页面：每种事件按颜色区分（用户蓝 / 回复绿 / 思考紫 / 工具橙 / 注入青 / 报错红），
长内容（注入、思考、工具结果超过 600 字，用户 / 回复超过 2000 字）先折叠，点「展开全文」看全部；
单轮详情顶部列出本轮所有注入的名字和字数，点一下跳到那一项；检索结果里命中的词会高亮。

## 注入是谁塞的（v0.1.3 起）

每条注入都标出来源，分四种：

| 徽标 | 含义 | 准确度 |
|---|---|---|
| **由 插件名 · 函数名** | 这个插件的这个 `on_llm_request` 处理函数在运行时改了请求（system prompt / 提问 / 额外文本块） | 精确 |
| **更早就在** | 会话流在最高优先级钩子（999999）拍第一张快照时它就已经在了：AstrBot 内核，或优先级比 999999 还高的插件 | 能确定“不是被包装的函数加的” |
| **没抓到是谁** | 请求被改了，但没有任何被包装的处理函数记到（后注册的处理函数、被后来的函数改写、或宿主内部不可用）；v0.1.7 起只记没人认领的那一部分，已经被别的处理函数认领的文字不再重复记一遍 | — |
| **疑似 X / Y**（虚线） | 在已装插件 / 内核源码里找到同名的 `<标签>` 字面量，只是推测 | 不是定论；旧档导入的回合只有这一种 |

做法：宿主按优先级逐个调用 `on_llm_request` 的处理函数。会话流在最高优先级的钩子里把其他插件登记的处理函数各包一层
（保持 `functools.partial(原函数, 实例)` 的形状，所以宿主重载插件时重新绑定新实例，不会调到旧实例，也不会叠包装），
包装在处理函数前后各拍一次 `system_prompt` / `prompt` / `extra_user_content_parts`，变了就记在这个插件头上。
会话流停用 / 卸载时把包装拆掉。顺带统计每个处理函数的次数和耗时（管理页「运行诊断」里能看到谁拖慢了请求前的处理）。

**这是伸手进宿主内部**：用到 `astrbot.core.star.star_handler.star_handlers_registry`、`EventType`、`astrbot.core.star.star.star_map`，
都不是公开 API。宿主改了的话，归属会自动退回“更早就在 / 疑似”，诊断包里 `runtime.attribution.status.available` 会是 false 并带原因，
不影响记录，也不影响别的插件。已对照 AstrBot 4.28.1 和 2026-10-09 master（commit d2fb912e）的源码确认登记表、
`call_event_hook`、插件管理器重绑定逻辑一致。

限制：注入只覆盖 `on_llm_request`；不是用处理函数改请求的（工具里改、猴子补丁内核）抓不到；
一个插件在同一个函数里既塞又被后来的函数改写，会标“后被改动”。

## 别的钩子上谁改了什么（v0.1.5 起）

同一套包装，现在覆盖更多钩子：

- **请求里的其他字段**（`on_llm_request`）：除了提示词，历史（`contexts`）、工具集（`func_tool`）、图片、模型被某个插件改了，
  会记一条「改动」事件（粉红色），写明“历史 20 → 2 条，删去 18 条：…”“工具集 28 → 27 个，去掉：xxx”，并标“由 插件 · 函数”。
  历史按内容比较，某个插件把每条都换成拷贝不算改动。
- **回复被改写**（`on_llm_response`）和 **发出前被改写**（`on_decorating_result`）：模型原话还是原来的「回复」事件，
  **只有实际要发出的内容和模型原话不一样时**，才在这一轮后面多出一条「实际发出」（金色），列出是谁、在哪个钩子、改写前后各是什么；
  一样就什么都不多记（忽略空白、@、引用、表情）。没抓到是谁改的会标“没抓到是谁改的”。
  “实际发出”取的是**最后一个插件钩子**（我们的优先级最低）时的消息链，所以不含宿主自己在那之后做的回复前缀 / 分段 / 语音 / 文转图。
  某个插件如果把长回复换成“首段”、其余稍后补发（如分段插件），这里就会显示首段，并标出是这个插件改的。
- **所有钩子上别的插件的处理函数耗时**：除了上面三个，还有等待 LLM、agent 开始 / 结束、工具前后、发送后——
  只统计次数和耗时，诊断包 / 管理页「运行诊断」里按最慢排，并写明在哪个钩子上。
- 页面：详情顶部多一行“本轮改动 N 项：…”，点一下跳到那一项；搜索的内容类型多一个「改动」，「回复」类型也搜“实际发出”。
- 限制：流式输出时发送前钩子宿主自己都说可能不生效，只在流式结束那一帧处理；事件被前面的插件终止传播时，
  我们最后那个钩子不会被调用，就没有“实际发出”；普通消息处理函数（指令等）没包装（它们可能是异步生成器，每条指令都经过，风险大）。

## 报错怎么算

- 一轮里工具有报错（工具结果里带 `error:` 之类），就算这轮有 1 次报错；
  会话卡片的报错数、「只看报错」筛选、总览报错数都按这个口径。
- 模型调用失败的那轮也记 1 次报错。

## 安装

把本目录复制到 AstrBot 的 `data/plugins/astrbot_plugin_session_flow/`，
在 WebUI 插件列表里启用。数据落在
`data/plugin_data/astrbot_plugin_session_flow/session_flow.db`（WAL）。

## 配置（_conf_schema.json）

| 项 | 默认 | 说明 |
|---|---|---|
| enable_record | true | 总开关 |
| exclude_umos | [] | 不记的会话，`*` 可代替一整段，如 `default:GroupMessage:*` |
| store_system_prompt | true | system prompt 原文存档（相同内容只存一份） |
| max_text_chars | 50000 | 单条正文上限，超了截断并标原长 |
| max_tool_result_chars | 20000 | 单条工具结果上限 |
| retention_days | 90 | 超期自动清理，0 = 永久保留 |
| link_provider_stats | true | 每分钟只读 AstrBot 自带用量表，对齐 token/失败状态 |
| stale_close_minutes | 30 | 开着超久无新事件的运行标“被打断” |
| diag_log_enabled | true | 写运行日志文件（`logs/session_flow.log`）并支持导出诊断包；改完要重载 |
| diag_log_runs | true | 日志里逐轮记「开始 / 结束」两行；群很活跃时可关掉 |

## 单轮导出（v0.1.6 起）

点开任意一轮，详情顶部有「导出本轮」「复制」。导出的是**这一轮的全部内容**，用来发给别人（或模型）看，和诊断包的区别是**含聊天正文**：

- 这一轮的基本信息（模型、用时、token——未命中缓存的输入 / 命中缓存的输入 / 输出、可用工具）；
- **上下文体积构成**和**时间拆分**（v0.1.8 起，见下）；
- **system prompt 全文**；
- **每一项注入的全文**，以及谁注入的（精确 / 更早就在 / 疑似）、来自系统提示词 / 提问 / 用户消息附加块、优先级；
- 按时间顺序的完整时间线：用户、注入、改动（历史 / 工具集 / 图片 / 模型）、思考、工具调用和结果、回复、
  实际发出（带每个改写者的“改写前 → 改写后”），每项带“距消息时间”的偏移；
- 文件末尾写明**没有**的东西：历史对话内容（只记了条数和谁改了历史）、真正发给模型提供商的最终请求体、
  超过「单段文本最大字数」被截断的部分、旧档没有注入 / 改动 / 实际发出。

格式二选一：Markdown（好读，默认；长文本都放在围栏代码块里，正文里有 ``` 也不会乱）或 JSON（不丢字段）。
会话 ID 和发送者默认打码，勾「保留原始会话 ID」才给原始值；**正文不做脱敏**（昵称、号码、群名原样），发出去前自己看一眼。
浏览器不让下载 / 不让写剪贴板时，「复制」会把全文放进页面上的文本框，全选复制即可。
接口：`GET api/export?id=<run_id>&fmt=md|json&raw=0|1&mask=0|1&mask_kinds=…`（后两个见下面“导出时屏蔽”），返回 `filename / mime / text` 和几个统计数字。

## 上下文体积构成与缓存命中率（v0.1.8 起）

单轮详情里多一块「上下文体积构成（估算）」，回答“这一轮几十万 token 的输入里，到底什么撑大的”：

- **量出来的**（每轮在最后一个请求钩子里数一遍，只数条数和字数，不存历史正文）：
  各角色（用户 / 助手 / 工具结果 / 系统）的条数、中文等宽字符数和其余字符数（中文等宽 = UTF-8 占 3 字节以上的字符：汉字、假名、
  全角标点、emoji；一个这样的字大约一个 token 或更多，英文几个字符才一个 token，所以分开数）、助手发起的工具调用次数、历史里的图片张数、
  最长的 5 条（角色、字数、开头 60 字）、system prompt 字数、**工具定义字数**（用 `ToolSet.openai_schema()` 序列化后数；
  这个 AstrBot 版本拿不到就写“没数到”）、本轮提问和注入块字数。AstrBot 内部的 `_checkpoint` 标记不发给模型，不算。
- **估算出来的**（在页面 / 导出里现算，不入库）：给中文等宽字符和其余字符各一个权重（1 和 0.3），得到各部分的“加权字数”，
  再用**服务商报的总输入 token（没命中缓存 + 命中缓存）**求一个换算系数，把各部分折算成 token——所以各行加起来正好等于服务商报的总数，
  每行的“约占”和“约 token”都标“估算”。**总数是准的，各行是折算的**；图片的 token 没算进去；
  如果估算和服务商总量差得太多（换算系数不在 0.5～2 之间），会写明“可能有图片、没数到的内容，或宿主在最后一个钩子之后又改了请求”。
  这一轮还没对上服务商 token 统计时，只给字数和条数。
- **缓存命中率** = 命中缓存的输入 ÷（没命中 + 命中），回合列表每张卡片上有一个“缓存 N%”的小徽标，详情的 token 行也写明。
  （注意 `token_in` 是**没命中缓存**的输入，不是总输入。）
- 对 2000 多条、百万字的历史数一遍，本机约 6～10 毫秒，在写库线程里做，不占事件循环。

## 每轮时间拆分（v0.1.8 起）

单轮详情里多一条分段条，把“消息时间 → 走到发送前最后一个钩子”切成几段（缺哪个时间点就少哪一段，不硬凑）：

| 阶段 | 含义 |
|---|---|
| 聚合等待 / 平台延迟 | 收到时间 − 平台给的消息时间。含聚合窗口、平台推送延迟和本机与平台的时钟差，只能当参考 |
| 内核准备 | 收到消息 → 开始跑请求钩子：AstrBot 取会话、拼请求、查知识库等 |
| 请求钩子 | 各插件的 `on_llm_request` 处理函数，同步等在每次请求前 |
| 起跑 | 请求钩子跑完 → agent 开始 |
| 模型 | agent 开始 → 结束，减去工具耗时 |
| 工具 | 各次工具调用的耗时之和 |
| 回复后处理 | agent 结束 → 走到发送前最后一个钩子（回复装饰、分段等） |

分段条下面折叠着“别的插件的处理函数耗时”表（钩子、插件 · 函数、次数、合计 / 最慢毫秒）：每个被会话流包装的处理函数的**每一次调用**都计时，
不管它有没有改东西。发送后（`on_after_message_sent`）的耗时不计入；v0.1.8 之前的记录没有这块。

## 顶部横幅（v0.1.8 起）

页面顶部只在真出问题时才亮一条（黄 = 功能退化但记录还在，红 = 影响记录）。页面每 30 秒自检一次：

- 注入归属不可用（`attribution.status.available` 为 false，常见于 AstrBot 刚升级、内部接口对不上）。**为空（null）= 还没有请求经过，不算故障。**
- 后台任务停了（写库、看门狗、对齐、清理）；
- 最近半小时有钩子报错；
- 写库队列堆了 200 个以上、单个写库任务卡了一分钟以上，或最近半小时写库失败过。

接口：`GET api/health` → `{problems:[{code, level, title, text}]}`，空列表 = 一切正常。

## 谁在往上下文里塞东西（v0.1.8 起）

管理页的一张表，按**来源插件**统计注入（只按字数，不换算 token）：有注入的轮数、项数、总字数、每次出现平均字数、出现率（占窗口内实时回合的比例）、
占全部注入字数的比例、各位置（system prompt / 提问 / 附加块）的字数分布。时间窗可选最近 7 天 / 30 天 / 全部，可选单个会话。
“内核 / 更早”和“未归属”各算一行；没精确归属、但在已装插件源码里找到同名标签的算“疑似 X”（只是推测）。
表下面另列“改动”统计：哪个插件改了历史 / 工具集 / 图片 / 模型，历史一共被删了多少条。接口：`GET api/stats/inject?days=7|30|0&umo=`。

## system prompt 对比上一轮（v0.1.9 起）

单轮详情的右上角有个小块，把这一轮发给模型的**完整 system prompt** 和同一会话里的上一轮比：
没变就写“和上一轮完全一样 ✓”；变了写“改了 N 处 · 新增约 X 字 / 去掉约 Y 字”和主要来源。点「看改了哪里」展开面板：

- **完整提示词（改动处红框）**：整份提示词都在，改动的地方画红框——红实线框 = 这一轮新增 / 改后的字；红虚线 + 划掉 = 上一轮有、这一轮没了的字或整行。
  同一行里只框变了的那几个字（时间 `07:21 → 07:23` 只框 `21 → 23`，一行很长只改了个数字也只框那个数字）；
- **只看改动处**：每处改动前后各留两行，中间没变的折叠成“已省略”；
- 「上一处 / 下一处」在改动处之间跳。

**每处改动都标是谁改的**（和“注入是谁塞的”同一套归属）：拿改动的那几行去上一轮 / 这一轮记到的 system prompt 注入块里找——

- 找到了：`由 <插件> · <处理函数> 加的`（精确归属）；上一轮有、这一轮没了的块写 `上一轮由 <插件> · <处理函数> 加的，这一轮没了`；
- 注入块有但没抓到是谁：`没抓到是谁 · <块名>`，源码里找到同名标签的再加 `疑似 <插件>`（只是推测）；
- 哪个注入块都不含这几行：`更早就在 · 内核或更高优先级`——AstrBot 内核拼的、优先级比会话流还高的插件改的，或者人设 / 配置变了；
- 相邻的两处改动如果来源相同（比如记忆块里改了一行又追加一行），算一处；来源不同的各算各的。

上一轮没存 system prompt（旧记录、设置里关了“存完整 system prompt”、原文被清理）时，会往前最多找 10 轮，对比最近一个存了的，并写明跳过了几轮；
找不到就写明没法比。同一会话里的第一轮写“第一轮，没有上一轮可以比”。两份提示词都超过 60 万字或 2 万行时不逐行比，只写大小。
接口：`GET api/sysprompt_diff?id=<运行 id>&lines=1`（不带 `lines` 只返回概要和改动处列表，不带逐行结果）。只读，不改库、不动记录逻辑。

## 导出一整页 / 搜索结果、导出时屏蔽（v0.1.8 起）

**一整页 / 搜索结果**：会话的回合列表上方有「批量导出」：「导出本页」把当前列表这一页（20 / 50 / 100 轮）导成一个文件；
搜索时多出「导出搜索结果」，把全部命中的回合导出（最多 200 轮）；「复制本页」复制到剪贴板。格式、会话 ID 打码、保留原始 ID 的选项同单轮导出。
文件按时间从早到晚，开头有目录，每轮一章（含体积构成和时间拆分）；**相同的 system prompt 按内容只放一份在文件末尾的附录里**，各轮写“见附录 S1”。
文件有大小上限（300 万字，中文约 9 MB），超了后面的回合不放进来，文件头和页面都会写明“选了 N 轮，只放了前 M 轮”。
接口：`GET api/export_many?umo=&scope=page|search&page=&size=&q=&kind=&fmt=&raw=&mask=&mask_kinds=`。

**屏蔽**：管理页「导出时屏蔽哪些内容」可以存规则（存在插件自己的库里，换浏览器 / 换机器也在），单轮导出和批量导出都生效：

- **默认一条规则都没有，什么都不屏蔽**（群聊最近消息那一块也不动）；号码、群名**不会**被自动打码；
- 规则 = 种类 + 名字：种类是 system prompt / 提问 / 回复 / 思考 / 工具 / 注入 / 改动 / 实际发出；名字可写注入块名、来源插件、工具名，
  不分大小写、支持 `*` 通配，留空 = 这一种全部；提问 / 回复 / 思考 / system prompt 没有名字，只能整种屏蔽；每条可以单独开关；
- 被屏蔽的段**整段删掉，不留占位**；文件头只写一句“有 N 段被屏蔽”；被屏蔽的注入不计入“注入一览”；
  如果屏蔽的注入同时写在 system prompt 或提问里，那里也一并抹掉；
- 屏蔽在后端做，被屏蔽的内容根本不进导出结果；
- 导出栏有“按屏蔽规则屏蔽（N 条）”勾选（有规则时默认勾上，取消 = 这一次不屏蔽），和“这一次再屏蔽…”（临时勾几种整种屏蔽，不进库）。

接口：`GET api/mask_rules`（规则 + 库里见过的名字，给输入框做提示）、`POST api/mask_rules/save`（`{rules:[{kind,name,on}]}`）。

## 运行诊断（v0.1.1 起）

插件出了问题想让别人帮看：插件页「管理」→「运行诊断」→ **下载诊断包**（一个 JSON）。

- **日志文件**：`data/plugin_data/astrbot_plugin_session_flow/logs/session_flow.log`，
  滚动保留最近约 4MB（1MB × 4 个）。内容：启动信息（版本、配置、AstrBot 库找没找到）、
  每轮运行的开始 / 结束（状态、步数、工具数、报错数、用时）、后台任务（看门狗 / 对齐 / 清理）、
  钩子和页面接口的报错（带完整 traceback）、钩子耗时超过 200ms 的警告。
- **诊断包**：环境与配置、库状态（各状态运行数、索引、文件大小、对齐率）、运行时状态（未关闭的运行、
  写库队列、4 个后台任务是否还活着）、每个钩子的次数 / 平均 / 最慢耗时 / 报错、最近 300 次钩子轨迹、
  最近 30 条报错、最近 40 轮运行的摘要、日志尾巴。
- **隐私**：不含任何聊天正文；会话 ID 默认打码成 `平台:类型:#哈希`（同一会话哈希不变）。
  勾选「保留原始会话 ID」才附一张对照表。配置里名字带 key / token / secret / password 的值会隐藏。
- 最近几十轮的摘要里，`tokens_in` 是**没命中缓存**的输入（provider_stats 的 `input_other`），命中缓存的在并排的
  `tokens_cached`；单看 `tokens_in` 小，不代表提示词短。
- 接口：`GET api/diag?raw=0|1&lines=N`。

## 接口（19 个）

`GET/POST /api/v1/plugins/extensions/astrbot_plugin_session_flow/api/<名字>`，
名字：`overview`、`runs`、`run`、`export`、`export_many`、`sysprompt`、`sysprompt_diff`、`search`、`active`、
`umo/summary`、`legacy/import`、`legacy/status`、`admin/stats`、`admin/purge`、`diag`、
`mask_rules`、`mask_rules/save`、`stats/inject`、`health`。

`runs`：`umo` 必填。带 `page`（和 `size`，1～200，页面用 20/50/100）是页码模式：新的在前，返回
`total / page / pages / size`；再带 `q`（检索语法同上）和 / 或 `kind`（`user|text|think|tool|inject|edit|error`）
就是搜本对话，每个回合多带 `hits`（最多 3 条命中事件）。不带 `page` 是老的游标模式（`limit` + `before`），行为没变。
返回 `{"status":"ok","data":…}`，出错 `{"status":"error","message":…}`。

## 已知限制

- 同一会话前后两轮在 5 秒内开跑时，对齐按开始时间最近连；极端连发仍可能连错，
  下一轮对齐（每分钟）不会自动纠正已连上的（`stats_id` 非空即视为已定）。
- 旧档导入去重靠“同 cid 已有 live 运行且用户原话前 200 字 + 回复前 200 字都相同”；
  有插件往 user 消息里追加内容时可能对不上而重复导入，宁可重复不误跳。
- 页面在离线 harness 里用无头 Edge 点过（亮 / 暗 / 390 宽），没在真 AstrBot WebUI 的 iframe 里点过。
- 体积构成里的 token 占比是按字数折算的估算，不是精确值；工具定义只有在宿主有 `openai_schema()` 时才数得到；图片的 token 没算。
- 时间拆分里“聚合等待 / 平台延迟”含平台时间戳与本机时钟的差；只统计会话流包装得到的别的插件的处理函数，发送后的不计。
- 库会略大：每轮多两个小事件（体积构成、时间，各约 1 KB）；v0.1.8 之前的记录没有这两块。
- system prompt 对比的“谁改的”是拿改动的行去注入块文本里找：注入块只记了被包装的处理函数加进来的部分，
  人设 / 内核拼的内容、优先级比会话流还高的插件改的，都只能写“更早就在”；一行太短（不到 3 个字）或只有符号的改动不找来源。
  对比的是同一个会话里时间上的上一轮，换了对话（新 cid）后两轮的提示词本来就可能不同。
- 检索一次最多展示 50 条命中里的前一部分（标“只展示前一部分”）；单轮事件超过 3 条同样只展示前 3 条。
- runs 列表的翻页游标 `next_before` 是不透明字符串，旧版 `sort_at:ord` 格式仍接受。
